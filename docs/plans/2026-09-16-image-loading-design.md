# 图片渐进展示与延迟加载

## 目标

避免大图下载时一截截露出。进入可视范围附近后再加载原图，先显示小尺寸模糊预览，下载及解码完成后展示清晰图。

## 规则

- 画布、素材窗口、编辑节点主图／参考图、提示词关联图和任务缩略图共用 `ProgressiveImage`。
- 根据实际显示位置和滚动裁剪判断可见性，提前 240px 开始请求；开始加载后不因移出视野反复重载。主动打开的大图立即加载。
- 原图下载期间保持透明，完成 `decode()` 后按统一 200ms ease-out 淡入。系统减少动态效果时立即切换。
- 内置图片使用随代码提供的 32px WebP 小预览；本地上传解码后生成同尺寸预览。未提供预览的外部图片首次使用中性占位，完整加载后为后续展示保存小预览；不提前下载原图来假装懒加载。
- 本地预览缓存最多 128 条，只保存小预览，不保留整张解码位图。真实图片比例、文件及画布坐标不变。
- 图片替换或组件移除后，旧请求不能更新新图片的展示状态；下载或解码失败显示错误提示。
- 图标、品牌资源和抠图编辑器的绘制原图保持原有处理。

## 实现

- `src/components/ProgressiveImage.tsx`：可见性、加载与解码状态。
- `src/image-previews.ts`、`src/image-previews.json`：动态缓存及内置小预览。
- `scripts/generate-image-previews.py`：使用 Pillow 重新生成内置预览，不改动原始素材；发布无需安装 Pillow。
- `src/motion.css`：统一清晰图淡入与占位退出。

本轮仅进行 TypeScript 编译检查，未进行浏览器交互验收。
