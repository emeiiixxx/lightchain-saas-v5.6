# Demo 代码与资源检查（2026-11-03）

检查范围：当前 v5.6 源码、两个页面入口、`public` 资源及本地生产构建。完成静态引用分析、文件 SHA-256 去重统计、TypeScript／Vite 构建和针对性回归检查；200 节点检查使用 jsdom，图片解码使用替身计数，均不代表浏览器帧率或真实 200 张图片压力测试。

## 结论

已修复 Flow 平移引起的节点内容重复渲染，启用屏幕外节点裁剪；Canvas 恢复改为共享图片解码并限制并发。已合并 OCR 的重复构建输出，并为重复图片统一显示请求。实际掉帧改善幅度仍需浏览器实测。

以下为修复前的审计基线，修复结果见末节。重复文件主要增加发布体积，不能直接等同于拖动画布卡顿。

| 项目 | 检查结果 | 影响与处理顺序 |
| --- | --- | --- |
| Flow 节点渲染 | 平移更新父组件视口状态，重新创建节点 JSX；`ReactFlowCanvas` 的图数据依赖 `children`，因此重新构建节点内容。未开启屏幕外节点裁剪。 | 优先测量及优化。分离视口更新与节点内容更新，再验证屏幕外渲染裁剪，保留框选、连线和拖动行为。 |
| Canvas 恢复图片 | `useCanvas.ts` 用 `Promise.all` 同时解码全部保存图片，同 URL 也逐项创建图片对象。预览缓存按图片对象区分。 | 可能增加首次恢复的解码及内存压力。可按 URL 共享解码、限制并发；不是每次平移都重新解码。 |
| 原始静态资源 | `public` 共 733 个文件、253.69 MiB；121 组字节完全相同的文件，多余副本共 63.91 MiB。 | 不同工作台重复存放同一素材。统一资源 URL 前需兼容已保存画布及任务中的旧 URL，不能按哈希直接删文件。 |
| OCR 构建资源 | 本次 `dist` 共 351.26 MiB；重复总量 98.58 MiB，较 `public` 多出的约 34.67 MiB 来自 OCR worker、WASM 的两份输出。 | 优化发布体积。OCR 已按需加载；这些文件不会因为普通拖动画布而全部加载。 |
| 大组件 | `App.tsx` 1182 行、`VideoWorkspace.tsx` 1328 行、`Workbench.tsx` 952 行、`useCanvas.ts` 1153 行。 | 业务与视口状态耦合，维护和回归成本较高；行数本身不是卡顿证据。优先拆出渲染边界，不为缩短文件而重写交互。 |
